## Points vérifiés

- Sans Redis et en mode `auto`, le processus de l'API enregistre le traitement de la file dans `enableRunner` ; avec Redis, c'est le worker (`DispatchWorker` appelle `enableRunner`), l'API ne consomme pas la file. Le traitement refuse une tâche (erreur, donc nouvelle tentative avec BullMQ) si le processus ne porte plus la répartition.
- Deux chemins simultanés (événement et tâche) pour la même course : un seul `dispatch_started`, une seule offre (verrou de la course dans `ensureStarted`).
- Le balayage ne touche pas les courses des processus en mode `manual` (pas de `dispatch_queued`, pas de ligne `ride_dispatches`) ni les répartitions ouvertes, en attente (`held`), à fenêtre close ou épuisées.
- `reassign` (opérateur) et `checkMovement` (surveillance du départ) relancent eux-mêmes la recherche comme avant ; seul le chemin « annulation du chauffeur » dépend de l'événement, désormais rattrapé.

## Pièges rencontrés

- `app.get(NotificationsOutbox)` ne rend pas l'instance du module des courses (quatre modules la fournissent) : `app.select(RidesModule).get(..., { strict: true })` pour un espion sur la boîte d'envoi de `RidesService`.
- `rides.service.ts` et `dispatch.service.ts` s'importent déjà en sens unique : les constantes partagées de la tâche vivent dans `dispatch-job.ts` (sans dépendance), sinon import circulaire et métadonnées d'injection indéfinies.
- Fichiers en CRLF : un script Node qui compare des lignes doit découper sur le marqueur de fin de ligne du fichier.
- TypeScript 7 natif plante en « out of memory » sous 500 Mo libres (quatre agents sur 6 Go) : relancer quand la mémoire se libère.
- Une commande d'arrière-plan tuée par sa limite de temps (15 minutes par défaut) alors qu'elle attendait puis tenait le verrou laisse le verrou à son nom (`db-lock.cjs release <nom>`) et des données de test non nettoyées ; un chauffeur de test qui accepte le terminal et les planifiées pollue ensuite `dispatch.e2e` (candidat de plus aux réservations planifiées). Lancer les passes sous verrou avec le délai maximal (2 h) et, après une passe tuée, neutraliser ses chauffeurs (`accepts_terminal = false`, présence retirée).
- Le simulateur SMS refuse les numéros finissant par `0000` ; `testPhone()` des aides peut en tirer un (une connexion sur 10 000) : échec de `loginByOtp` sans rapport avec le code testé.
- `with-env.cjs` relance la commande par le shell Windows : une requête SQL passée en argument y perd ses guillemets ; `db-query.cjs` charge le `.env` lui-même, l'appeler directement.
